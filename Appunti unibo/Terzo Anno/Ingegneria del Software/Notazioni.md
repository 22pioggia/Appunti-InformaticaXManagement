Abstraction

Model
- A representation of the system under analysis that answers as the system does for a given set of questions
- All models are in simulacra, that is, simplified reflections of reality, but, despite their inherent falsity, they are nevertheless extremely useful

Stakeholder

FURPS+
- **Functional**: *features, capabilities, security.*
- **Usability**: *human factors, help, documentation.*
- **Reliability**: *frequency of failure, recoverability, predictability.*
- **Performance**: *response times, throughput, accuracy, availability, resource usage.*
- **Supportability**: *adaptability, maintainability, internationalization, configurability.*
- +: *implementation, interface, operations, packaging, legal.*

>A simpler UC specification template 
- ID
- Actors
- Pre-conditions
- Main sequence
- Alternative sequences
- Post-conditions

- **Pre-conditions** are prerequisites that have to be valid in order for the use case to take place
- **Post-conditions** are changes to the state of the system or its environment that take place when the use case is terminated

- **Process**: set of coordinated activities leading to a goal
- **Software process**: the goal is software production / deployment / evolution / maintenance

**Refactoring ->** a disciplined technique for restructuring a software system so that its internal structure is modified without changing its external behavior

***Pattern*** = *Each pattern describes a problem which occurs over and over again in our environment, and then describes the core of the solution to that problem, in such a way that you can use this solution a million times over, without ever doing it the same way twice*
